# 轻量化、高召回、低漏检的全新领域论文检索方案（从头重构，抛弃原复杂流水线）
## 核心设计思想
原方案核心问题：**多层串行、多轮LLM、硬阈值截断、雪球上限、diff逻辑漏洞、多段过滤层层丢论文**，为了兜底叠加了大量补丁，复杂度爆炸但召回仍有系统性漏洞。
新方案遵循4个极简原则：
1. **先广后精，先把所有潜在论文捞全，再统一过滤，绝不中途提前裁剪**；
2. **双基准校验，不单一依赖LLM输出的seminal列表**，杜绝源头真值缺失；
3. **取消多层人工匹配规则、衍生论文特殊标记、确定性diff补丁**，交给LLM统一做语义匹配；
4. **单轮可扩展闭环，一次检索产出候选池后允许二次扩搜，无硬Seed上限**；
5. **严格控制LLM调用次数，不碎片化调用，集中批量处理，降低不确定性**。

适用目标：输入领域名称，最大化召回该领域里程碑、前沿、分支核心论文，同时兼顾执行速度、API成本、工程易维护。

# 整体架构（极简三段式，无复杂子步骤嵌套）
## 总流程
用户输入领域名称
1. **全域粗召回阶段（无LLM，纯API拉取，最大化广度）**
2. **候选池合并+去重（统一存储元数据，不提前过滤）**
3. **LLM统一筛选+缺失论文补充（仅2次LLM调用，所有校验、匹配、补全统一在这里完成）**

无分步预过滤、无分段匹配、无前置确定性diff、无多层保护链，所有“判断是否核心论文”的语义工作全部交给LLM，避免人工规则漏洞。

## LLM调用总量固定仅2次，远低于原方案5+N
1. 第1次LLM：生成多源检索词+领域核心标志性工作名称（仅用于辅助粗召回）
2. 第2次LLM：统一处理全量候选池，完成三件事：标记里程碑、筛选代表论文、输出检索池缺失的关键论文清单（用于二次补搜）

# 阶段1：全域粗召回（核心解决原方案漏检根源，彻底放开限制）
## 1.1 双检索源并行：Semantic Scholar 主检索 + arXiv 辅助检索
放弃原方案“仅arXiv为主、SS仅做雪球”的失衡架构，双源平等并行：
1. **Semantic Scholar 全文语义检索（主入口）**
   - 输入：LLM生成的领域宽泛query + 领域标准名称
   - 优势：原生覆盖CVPR/ICRA/ECCV等不上arXiv的顶会、工业白皮书、期刊论文，语义匹配而非单词匹配，解决术语变体问题；
   - 无返回条数硬截断，分页拉取直到结果相关性断崖下跌（自动停止，不固定120上限）
2. **arXiv多关键词检索（补充入口）**
   - LLM输出领域细分关键词、缩写、方法名批量检索；
   - 保留单词级宽松匹配，弥补SS对小众缩写检索弱的短板；
3. **补充：SS基础论文反向滚雪球（无5 seed硬上限）**
   从SS检索Top30高相关论文全部作为seed，无数量限制，批量拉取每篇一级引用/被引；
   解决单条技术分支上下游论文缺失问题；
   取消原方案seed≤5的硬性约束，从根源解决多里程碑领域雪球扩展不足。

## 1.2 粗召回阶段**零过滤、零裁剪**
所有检索结果直接合并、仅做ID去重，不执行：
- 不提前限制120候选池；
- 不提前按引用量排序剔除新论文；
- 不提前用arXiv分类白名单过滤；
- 不人工token匹配标记seminal、不区分衍生工作；
所有无关、衍生、跨学科论文全部进入总候选池，过滤后置，避免中途永久丢失关键论文。

## 1.3 粗召回兜底补全（解决原recovery碎片化问题）
LLM第一轮输出领域标志性论文清单（方法名、作者、年份），批量执行3条检索，结果全部并入候选池：
1. SS精确标题检索（抓非arXiv经典工作）
2. arXiv作者+年份检索（规避关键词不匹配）
3. arXiv标题关键词检索
粗召回阶段一次性完成所有补搜，不拆分成后置recovery步骤，逻辑集中。

## 1.4 API限流简化
统一全局请求间隔，统一指数退避重试，不区分query类型单独配置；SS/arXiv请求失败仅跳过单条查询，不中断整条召回链路。

# 阶段2：候选池统一合并与标准化
1. 统一去重：arXiv ID / SS paper ID / 标题模糊匹配三重去重，合并重复论文的引用、摘要、年份、作者信息；
2. 统一元数据标准化：标题、年份、作者、摘要、引用量、来源（arXiv/SS/雪球扩展）、分类；
3. 不做任何筛选，完整候选池直接送入LLM批量处理。

# 阶段3：LLM统一处理（仅1次LLM批量调用，替代原方案diff、匹配、遴选、force-include四套复杂逻辑）
输入：全量候选池（无提前删减，包含几百篇原始候选）
Prompt一次性交付LLM完成4项任务，彻底抛弃人工设计的分词、缩写、衍生、短关键词匹配规则（人工规则永远存在边界漏洞）：
1. **标记领域里程碑论文**
   基于领域知识+论文发表时间、贡献，区分：原始奠基工作 / 分支衍生改进工作，不会出现“衍生论文顶替原版、掩盖缺失”的漏洞；
2. **筛选代表性子集**
   按时间线、技术路线、引用量均衡挑选固定数量论文（如20篇），强制保证每个技术分支、每一年代都有覆盖，低引用新方法不被挤出；
3. **输出当前候选池缺失的关键论文清单**
   LLM依靠自身领域知识库，列出所有明显遗漏的经典/前沿论文，包含标题、作者、年份；
4. **标记明显无关论文**
   输出可直接过滤的跨领域、无关论文列表，后置统一剔除，而非中途拦截。

## 3.1 二次补搜闭环（原方案完全缺失的迭代能力）
LLM输出的缺失论文清单，再次执行一轮粗召回兜底检索（同阶段1三条检索路径），新增论文并入候选池；
形成**一次召回→LLM查漏→二次补搜**的闭环，解决单次检索漏检问题。
原方案是单轮线性流程，捞完即结束，无二次扩充能力。

## 3.2 最终子集生成（后置过滤，完全可控）
1. 剔除LLM标记的无关论文；
2. 合并原始精选论文 + 二次补搜到的里程碑论文；
3. 强制保留所有LLM标记的奠基里程碑，仅裁剪衍生改进论文；
4. 输出最终论文列表，送入缓存下载、分析流水线。

# Step4 缓存下载、分析、生成MD（复用原有稳定模块，不改动）
paper_cache.py / one_shot_analyzer / generate_evolution_md 完全复用，仅输入改为新方案输出的论文列表，无侵入式修改。

# 关键对比：新方案 vs 原复杂方案，解决全部原有漏检缺陷
## 1. 解决P0致命缺陷
1. **取消人工diff+token匹配规则**：不再出现衍生工作顶替原版里程碑、不触发补搜的逻辑漏洞，全部语义判断交给LLM；
2. **移除雪球seed≤5硬上限**：所有高相关论文均可作为引用扩展种子，多里程碑领域完整扩展；
3. **增加二次补搜闭环**：捞到遗漏论文后重新检索，挖掘其上下游关联论文；
4. **双源并行检索（SS为主、arXiv为辅）**：非arXiv顶会、工业论文初次即可大量召回，不依赖雪球间接获取；
5. **真值不单一依赖首轮LLM**：粗召回数据反向辅助LLM查漏，双向校验，源头漏写的论文可通过LLM缺失清单补回。

## 2. 解决P1高频漏检缺陷
1. **粗召回零前置过滤**：新发表低引用里程碑不会在预过滤阶段被提前剔除；
2. **分类白名单后置，由LLM语义判断无关论文**：跨学科交叉领域核心论文不会被硬编码分类直接拦截；
3. 补搜同时支持第一/通讯作者检索，不再局限仅first_author；
4. SS检索分页拉取完整引用列表，解决分页截断丢失关联论文问题。

## 3. 大幅降低整体复杂度
原方案痛点：分步匹配、分步过滤、分步补搜、多层LLM碎片化调用、十多段子流程、大量人工规则补丁，维护成本极高。
新方案仅三大阶段：全域粗召回 → 候选池合并 → LLM统一筛选+闭环补搜，逻辑高度收敛；
- 删掉模块：1.3人工匹配规则、1.6确定性diff、1.8 force-include多层保护链、分段预过滤；
- LLM调用从最少5+N降至固定2次，成本更低、输出波动更小；
- 所有语义判断统一收口，不用维护大量边界补丁。

# 配套工程优化（轻量化设计，降低运维成本）
## 1. Fast快速模式（极简降级）
仅保留SS语义检索Top20高引论文，跳过LLM两次调用、雪球扩展、二次补搜，极速预览，逻辑清晰。

## 2. 容错简化（统一异常处理，不再分场景定制逻辑）
1. arXiv/SS API失败：仅跳过当前查询，保留其余结果继续执行；
2. LLM解析失败：降级为按引用+时间分层抽样，不丢失全部候选；
3. 二次补搜全部无结果：静默结束，保留首轮全部候选；
4. PDF下载逻辑完全复用原有增强逻辑（超时交互、--no-download）。

## 3. 代码结构简化
1. 仅保留一个统一 `paper_retriever.py`，内部分三大函数：`broad_recall()`、`merge_candidates()`、`llm_filter_and_fill_missing()`；
2. 移除分散在各子步骤的匹配、过滤、补搜碎片化代码；
3. 入口脚本参数保留，仅底层检索逻辑替换，上层调用无感知。

# 完整执行链路流程图（极简）
```
用户输入领域名称
├─ LLM 1：生成检索关键词 + 领域经典论文清单（1次LLM）
├─ 阶段1 全域粗召回（无过滤）
│  ├─ SS语义检索（分页拉满）
│  ├─ arXiv多关键词检索
│  ├─ SS批量雪球扩展（无seed上限）
│  └─ 经典论文兜底三路径检索
├─ 合并所有论文，全局去重 → 完整候选池
├─ LLM 2：批量处理全量候选（1次LLM）
│  ├─ 标记里程碑 / 衍生论文 / 无关论文
│  ├─ 均衡筛选代表论文
│  └─ 输出候选池缺失的关键论文清单
├─ 二次闭环补搜：对缺失论文再次执行粗召回逻辑，新增论文并入候选池
├─ 后置过滤：剔除无关论文，强制保留全部奠基里程碑，裁剪衍生论文
└─ 输出最终论文列表 → 进入缓存下载、one-shot分析、生成MD
```

# 核心优势总结
1. **召回上限更高，系统性漏检全部修复**：双检索源、无前置裁剪、无seed硬限制、二次补搜闭环、语义替代人工规则；
2. **架构极简，可维护性大幅提升**：删除数十行人工匹配、diff、分层过滤补丁，逻辑集中；
3. **LLM调用更少、更稳定**：固定2次批量调用，避免碎片化多次调用带来的输出不一致；
4. **容错简单清晰**：所有过滤后置，不会出现中途永久丢失论文；
5. 兼容原有下游所有模块，改造范围小，迁移成本低。
