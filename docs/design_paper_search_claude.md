这份文档比上一版又进了一步（新增了短 keyword 降级匹配、衍生工作降权、白名单过滤），但如果"关键论文仍然召回不了"这个症状还在复现，我认为原因很明确：**这版文档没有采纳我们上一轮已经定位到的核心结论**——匹配逻辑依然是纯 token 规则，而且依然只用标题不用摘要。1.3 节把规则做得更精细了（长/短 keyword 分流、缩写复合词降权），但精细化规则打的是"字符串相似度"这个地基上的补丁，地基本身（词面重叠 ≈ 语义等价）没有换掉。LSS 这类"标题零重叠但语义完全对应"的论文，无论规则多精细，都过不了 token 匹配这一关。

具体缺陷列出来，然后给一个我认为能实质性解决召回问题的重设计方案。

## 现有设计的缺陷

**1. 匹配文本仍然只用标题，摘要没有被纳入**

1.3 节所有规则描述的都是"作为子串出现在标题"，"匹配占比≥70%"里的分母分子也都是标题词。摘要信息完全没进入匹配环节。这是最直接、成本最低就能修的一处遗漏——LSS 的摘要几乎必然包含"bird's-eye-view"之类的概念词，仅仅把摘要拼进匹配文本，召回率就会有明显提升。

**2. 匹配判定逻辑本质仍是 token overlap，只是规则更多了**

短 keyword 降级匹配、缩写独立校验，都是针对已发现的具体失败案例（LSS 的短标题问题、FQ-PETR 的衍生词问题）"对症下药"式打的补丁。这种做法的风险是：**每次真实运行中冒出一个新的失败模式，就要再加一条规则**，规则会越叠越多、越叠越脆，而且规则之间可能互相打架（比如"短 keyword 子串匹配"和"缩写复合词降权"对 "BEV-Former" 这种命名会不会互相误判，谁的优先级更高，没有说清楚）。这是典型的规则系统在长尾问题上的失控模式。

**3. 确定性 Diff 抓出了 unmatched，但 Recovery 路径大概率会用同一套脆弱逻辑再失败一次**

1.9 的三条 recovery 路径里，"arXiv 关键词检索"本质上还是关键词字符串搜索——如果 LLM 生成的 keyword 本身就没抓住论文的"怪异标题"（LSS 这种），关键词搜索大概率还是搜不到，这在我们上一轮的实测里已经验证过（LSS 的 recovery 确实没找回来）。"SS 标题语义检索"这条路径名字叫"语义"，但没说清楚具体机制是调 SS 的常规搜索接口（本质还是短语匹配，1.2 节自己诊断过这条路缺陷很大），还是真正的 embedding 相似度检索——如果是前者，这条"语义"路径其实是假的，等于兜底手段和主检索手段犯了同一种错误。

**4. 没有"确认彻底找不到"的显式收尾机制**

七个容错场景里，"遗漏论文恢复单路径失败：自动切换…全部失败则静默跳过"——这意味着即便三条 recovery 路径全部失败，系统也只是**悄悄放弃**，不会在最终输出或日志里明确告诉用户"LSS 这篇 milestone 论文经过 diff 检测+三路恢复仍未找到"。这个信息其实是免费的（diff 阶段本来就知道），但没有被暴露出来，用户完全不知道要不要手动补。

**5. 里程碑真值清单本身没有外部校验**

整条保护链的源头——1.1 步 LLM 生成的"里程碑论文清单"——完全依赖 LLM 自身记忆，没有任何外部信息交叉验证。如果 LLM 知识本身有盲区（某个子方向、某篇论文在训练数据里覆盖不足），保护链再精密也保护不到一份本来就不完整的清单。

**6. Snowball 只做一跳，遇到"两跳关联"论文依然覆盖不到**

5 个 seed 做一阶引用扩展，如果关键论文和已匹配 seed 之间隔着两跳（比如是某篇未被选为 seed 的论文的引用），依然搜不到，而且没有针对"多轮 unmatched 之后还要不要扩大跳数"的机制。

## 如果让我重新设计，保证关键论文尽量都能被召回

核心思路只有一条：**把"匹配"这个判断任务从"字符串规则"整体换成"语义判断"，并且给"确认彻底找不到"一个显式的、可见的终态**，而不是继续在规则层面打补丁。

### 改动一：里程碑匹配 —— 从 token overlap 换成 embedding 相似度（标题+摘要）

- 对 LLM 生成的每条里程碑描述（title_keywords + 已知贡献点，如果 LLM 能顺带生成一句话摘要式描述更好），和候选池里每篇论文的"标题+摘要"拼接文本，各自算一次 embedding；
- 用余弦相似度排序，取每条里程碑相似度最高的候选，超过阈值即判定为匹配；
- 这一步直接替换掉 1.3 节里所有的分词/子串/占比规则，不再需要"长 keyword / 短 keyword / 缩写降级"这些分支逻辑——语义相似度天然能处理短标题（PETR）、怪异标题（LSS）、同义表述（"BEV representation" vs "top-down feature map"）等各种情况，规则数量从多条降到一条统一逻辑。
- 衍生工作误判（FQ-PETR）在这个方案下也会自然缓解：衍生论文标题词面像，但摘要讲的具体改进点和原始论文不同，embedding 相似度不会像 token overlap 那样虚高。

### 改动二：里程碑匹配确认 —— 候选量小的阶段直接上 LLM 判定，不用规则

里程碑匹配这一步的候选量级很小（几十个里程碑 × 每个不超过 5-10 个相似候选），完全负担得起做一次批量 LLM 判定：把"LLM 说的这篇论文是什么"和"embedding 相似度最高的几个候选"一起丢给 LLM，让它直接回答"是/否/哪一个"，而不是靠阈值卡。这一步比 embedding 更贵一点，但可以只在 embedding 相似度落在"不确定区间"（比如 0.6-0.85 之间，太低直接不匹配，太高直接匹配）的案例上触发，成本可控，且能同时利用作者、年份等结构化信息做交叉验证，比规则更抗噪声。

### 改动三：Recovery 路径也要换血，不能是"用同一把钥匙开同一把锁"

三条路径改成：

1. **arXiv 作者+年份检索**（不变，这条本来就不依赖标题词面，保留）；
2. **SS 真正的语义检索**——用 embedding 相似度去查 SS 论文库（或者如果 SS 没有现成的语义检索接口，退化为：SS 关键词检索返回的候选，同样用 embedding 相似度重新排序，而不是直接信任 SS 自己的相关性排序）；
3. **新增：向 LLM 直接追问**——如果前两条路径都没找到，把"这篇论文找不到"的情况连同 LLM 自己给出的描述一起反馈给 LLM，追问一次"你确定这篇论文存在吗？能否提供更精确的信息（比如准确年份、会议、arXiv ID 猜测）？"，作为最后一道人工干预前的自纠错机制。

### 改动四：显式的"确认丢失"终态，而不是静默跳过

Diff 检测到的 unmatched milestone，经过三路 recovery 全部失败后，**必须写入最终输出的一个 `confirmed_missing_seminal_papers` 字段**，在生成的 markdown 报告末尾或者日志里明确列出来（比如"以下里程碑论文经检索未能找到，建议人工确认：LSS (2020)"）。这个改动成本几乎为零（数据本来就有），但把"隐性丢失"变成"显性提示"，是目前设计里最大的信息浪费。

### 改动五（可选，收益高）：用一篇真实 survey 论文校准里程碑清单

在 1.1 步之后，额外搜一篇该领域近 1-2 年的 survey/review 论文，抽取其中引用的关键工作列表，与 LLM 自己生成的里程碑清单取并集。这一步不需要精读 survey 全文，只需要抓它的 related work / 引用列表做字符串级别的论文名提取即可，成本很低，但能补上 LLM 自身知识盲区导致的"清单本身就漏了"这类问题——这是目前整条保护链里唯一没有外部校验的源头环节。

---

**总结**：现有设计的三层保护链（预过滤、LLM 遴选、强制补全）解决的是"匹配上了之后如何不被挤掉"的问题，这部分已经做得很扎实；但真正决定召回上限的是"匹配"这一步本身的判断力，而这一步至今还停留在字符串规则层面。把匹配逻辑换成 embedding/LLM 语义判断，再加一个"确认丢失"的显式终态，我认为是解决"关键论文总是漏"这个反复出现症状的根本改法，而不是继续在 token 规则上做加法。
